# Howson's theorem through finite cores and Kurosh decomposition

This repository formalizes the finite-rank form of Howson's theorem: the
intersection of two finitely generated subgroups of a finite-rank free group
is finitely generated.

```lean
theorem HowsonChallenge.howson_intersection_fg
    {α : Type*} [Finite α]
    (H K : Subgroup (FreeGroup α))
    [Group.FG H] [Group.FG K] :
    Group.FG (H ⊓ K : Subgroup (FreeGroup α))
```

The proof is an explicit finite-core argument. Marshall Hall's theorem first
places `H` as a free factor of a finite-index subgroup `L` of the ambient
free group. The subgroup `K ∩ L` is finitely generated by the finite-index
Schreier theorem. After transporting this subgroup across the binary
free-product bridge `L ≃* H ∗ Q`, the Kurosh development supplies the actual
conjugate-intersection factor. Its inclusion-induced homomorphism into
`H ⊓ K` is proved surjective, so finite generation descends to the desired
intersection.

The earlier Marshall Hall and Bass--Serre/Kurosh repositories are retained as
supporting formalizations. They are recorded as related formalizations in
`formalization.yaml`; the new mathematical source formalized here is
Howson's intersection theorem.

## Repository map

- `Challenge.lean` is the small Mathlib-only Palomar statement surface.
- `Solution.lean` connects that surface to the checked implementation.
- `Howson/Intersection.lean` proves the main theorem.
- `Howson/KuroshFG.lean` proves finite generation of the selected Kurosh
  factor.
- `Howson/BinaryKurosh.lean` supplies the binary free-product equivalence.
- `MarshallHall/` contains the inclusion-compatible Hall and finite-core
  development used as a supporting layer.
- `GraphCoveringTheory/` contains the Bass--Serre/Kurosh development used as
  a supporting layer.
- `comparator.json` records the exact Challenge/Solution correspondence.
- `formalization.yaml` records provenance, scope, and related formalizations.

- M. Hall, Jr., [Subgroups of finite index in free groups](https://doi.org/10.4153/CJM-1949-017-2), *Canadian Journal of Mathematics* 1 (1949), 187--190.

## Verification

The project is pinned to Lean 4.32.0 and Mathlib v4.32.0.

```text
lake build
lake env lean --src-deps Challenge.lean
ruby scripts/validate-formalization.rb
./scripts/verify-comparator.sh
```

`Challenge.lean` contains one deliberate proof hole because Palomar checks the
public statement against `Solution.lean`. `Solution.lean` and the
implementation modules contain no proof holes or custom axioms.
